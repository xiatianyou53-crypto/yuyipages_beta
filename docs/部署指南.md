# 部署指南（管理员 / 技术负责人）

> 本文档面向"负责把网站上线的人"。分步执行，按顺序来即可。
> 文档末尾有**上线验证清单**和**常见问题排查**。

---

## 0. 要准备的东西 & 整体架构

你需要：
- 一个 **GitHub** 账号（存放网站源码与内容）
- 一个 **Cloudflare** 账号（托管与全球加速，免费额度足够）
- 可选：本机安装 git、Hugo（用于本地预览，非必须）

架构与数据流（记住这个图，后面全围绕它）：

```
社员打开 网站/admin  →  登录（方案A: GitHub账号 / 方案B: 邮箱）
        │  编辑内容 + 拖拽上传 PDF/图片
        ▼
Decap CMS 把改动写回 GitHub 仓库的 main 分支
        ▼
Cloudflare Pages 检测到新提交 → 自动 hugo --minify 重新构建
        ▼
网站自动更新（一般几十秒内）
```

**两个后台登录方案（先决定用哪个）：**

| | 方案 A：Cloudflare + GitHub（推荐） | 方案 B：Netlify git-gateway（最省事） |
|---|---|---|
| 托管 | Cloudflare Pages | Cloudflare Pages 或 Netlify |
| 登录方式 | 社员用 GitHub 账号 | 社员用邮箱+密码 |
| 额外组件 | 需部署一个 OAuth Worker | 无需额外组件 |
| 维护难度 | 中（一次性配置） | 低 |
| 适合 | 你/社团有 GitHub 习惯 | 社员几乎不用 GitHub |

> 本仓库当前 `static/admin/config.yml` 默认按**方案 A** 的 `github` 后端编写（带占位符）。
> 若你选方案 B，请按下文"方案 B"修改该文件。

## 1. 建 GitHub 仓库并推送代码

在 GitHub 网页新建一个 **私有(Private)** 仓库（内容含校报，建议私有），不要勾选任何初始化文件。
然后在项目根目录执行：

```bash
git init
git add -A
git commit -m "init：校园语意报社官网"
git branch -M main
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git push -u origin main
```

> 仓库里的 `.gitignore` 已排除 `public/` 构建产物，不会误提交。
> `oauth-worker/`、`docs/`、`_tools/` 属于项目文件，应一并提交。

---

## 2. 在 Cloudflare Pages 创建站点（方案 A 与 B 共用此步）

1. 登录 Cloudflare → 左侧 **Workers & Pages** → **Create → Pages → Connect to Git**。
2. 授权 GitHub，选择刚才的仓库。
3. 构建配置（Framework preset 选 **Hugo**，若没自动填则手动写）：
   - **Production branch**：`main`
   - **Build command**：`hugo --minify`
   - **Build output directory**：`public`
   - **Environment variables**：添加 `HUGO_VERSION` = `0.165.0`（锁定版本，避免未来 Hugo 变动影响构建）
4. 点 **Save and Deploy**。等约 1 分钟，成功后你会得到 `https://<你的项目名>.pages.dev` 地址。
5. 先访问这个地址确认网站能打开。**先不要急着改任何东西。**

---

## 3. （推荐）绑定自定义域名

Pages → 你的项目 → **Custom domains → Set up a custom domain**：
- 输入你的域名（如 `yuyi.xxx.cn`），Cloudflare 会提示加一条 **CNAME** 记录指向 `<项目名>.pages.dev`。
- 添加后等待 DNS 生效（几分钟到几十分钟）。
- 国内访问建议用自己的域名；`*.pages.dev` 在国内访问可能不稳定。

> 绑定后，把正式域名填到两处并重新部署（见第 6 步）：
> - `config.yaml` 的 `baseURL`
> - `static/admin/config.yml` 的 `site_url`

---

## 4. 后台登录 —— 方案 A：Cloudflare + GitHub + OAuth Worker

这一节让"社员用 GitHub 登录、Decap 能自动写回仓库"。共 4 步。

### 4.1 创建 GitHub OAuth App
1. GitHub → 头像 → **Settings → Developer settings → OAuth Apps → New OAuth App**。
2. 填写：
   - **Application name**：`语意报社 CMS`
   - **Homepage URL**：你的站点地址（如 `https://yuyi.xxx.cn`）
   - **Authorization callback URL**：先临时填 `https://<你的项目名>.pages.dev/admin/`（第 4.2 部署 Worker 后再改成 Worker 的 `/callback`）
3. 创建后记下 **Client ID**，并点 **Generate a new client secret** 生成 **Client secret**（只显示一次，立即保存）。

### 4.2 部署 OAuth Worker（登录与自动提交的引擎）
1. 安装登录 Cloudflare CLI（本机操作）：
   ```bash
   npm i -g wrangler
   wrangler login
   ```
2. 在仓库的 `oauth-worker/` 目录下：
   ```bash
   cd oauth-worker
   wrangler secret put GITHUB_CLIENT_SECRET   # 粘贴 4.1 的 Client secret
   ```
3. 编辑 `oauth-worker/wrangler.toml`，在 `vars` 里加入：
   ```toml
   GITHUB_CLIENT_ID = "粘贴你的 Client ID"
   ```
4. 部署：
   ```bash
   wrangler deploy
   ```
   记下输出的 Worker 域名，例如 `yuyi-oauth.你的子域.workers.dev`。
5. 回 GitHub 的 OAuth App，把 **Authorization callback URL** 改成：
   `https://yuyi-oauth.你的子域.workers.dev/callback`

### 4.3 回填站点后台配置 `static/admin/config.yml`
打开文件，把 backend 段改成（注释行去掉）：

```yaml
backend:
  name: github
  repo: <你的用户名>/<仓库名>                 # 例 lnsy/school-news
  branch: main
  base_url: https://yuyi-oauth.你的子域.workers.dev   # 4.2 的 Worker 域名
  auth_endpoint: auth
```

并把顶部的 `site_url` 改成真实域名。

### 4.4 用 Cloudflare Access 加一道登录门（强烈建议，保护 /admin）
1. Cloudflare 控制台 → **Zero Trust → Access → Applications → Add an application → Self-hosted**。
2. **Application domain** 填：`<你的项目名>.pages.dev` 或你的自定义域名，**Path 填 `/admin`**。
3. **Policy**：名为"社员"，Action 选 **Allow**，规则用邮箱/一次性验证码或社交登录，
   只允许你邀请的社员邮箱（这样即使有人有 GitHub 权限也进不来后台）。
4. 保存后，访问 `/admin/` 会先要求过这道门，再进入 Decap 的 GitHub 登录。

> 完成后推送所有改动，Cloudflare 会自动重新构建。访问 `/admin/` 测试（见第 7 步）。

---

## 4b. 后台登录 —— 方案 B：Netlify git-gateway（不想碰 Worker 时选这个）

1. 把 `static/admin/config.yml` 顶部 backend 整段替换为：
   ```yaml
   backend:
     name: git-gateway
     branch: main
   ```
2. 网站托管到 **Netlify**（推荐，能一条龙）：把仓库连到 Netlify，
   构建命令 `hugo --minify`、发布目录 `public`。
   若你仍想用 Cloudflare Pages，则后台登录/自动提交要另外想办法，故方案 B 建议直接用 Netlify。
3. Netlify 后台 → **Identity → Enable**（开启身份）。
4. **Identity → Registration**：选 "Invite only"（仅邀请）。
5. **Identity → Invite users**：输入社员邮箱发送邀请；社员点邮件链接设置邮箱+密码。
6. 这样 `/admin/` 登录用的是 Netlify 的邮箱账号，改动同样写回 GitHub 并触发部署。
   - 需要"管理员审核后才上线"：把上面第 1 步再加一行 `publish_mode: editorial_workflow`。
   - 迁移注意：若后续想换回方案 A，只需还原 backend 段。

---

## 5. 回填正式域名并触发一次干净发布

无论方案 A/B，最后都要把占位域名替换成真实地址并重新构建：

1. 编辑 `config.yaml`：
   ```yaml
   baseURL: 'https://你的正式域名/'   # 例 https://yuyi.xxx.cn/
   ```
2. 编辑 `static/admin/config.yml` 的 `site_url` 为同一域名。
3. 推送，Cloudflare（或 Netlify）会自动重新构建并上线。

## 6. 上线验证清单（建议照做一遍）

**公开站点**
- [ ] 首页能打开，轮播、社团简介、"最新一期校报"、"最新 3 篇文章"正常
- [ ] `/newspaper/` 校报按年份分组显示；点卡片进详情能 iframe 预览 + 下载 PDF
- [ ] `/posts/`、`/about/` 正常；手机端导航能展开
- [ ] 浏览器地址栏标题与 description 正常（SEO）

**后台真实试运行（最关键）**
- [ ] 访问 `/admin/` 能正常进入登录
- [ ] 新建一期"校报"：上传一个真实 PDF（建议 <10MB）+ 填期数/日期 → Save
- [ ] 等部署完成，回到 `/newspaper/` 能看到新的一期、能预览下载
- [ ] 新建一篇"文章"→ Save → `/posts/` 能看到
- [ ] 上传一张图片当封面，前端正常显示

> 若第 2 项成功，说明"上传 → 自动 commit → 自动构建 → 上线"整条链路通了，部署即完成。

## 7. 常见问题排查

| 现象 | 可能原因与处理 |
|---|---|
| `/admin/` 打不开 / 一直加载 | Decap 脚本来自 unpkg CDN，需联网；或 Cloudflare Access 配置有误，检查 Path 是否为 `/admin` |
| 能进后台但点"登录"没反应 | 方案 A：OAuth App 的 Callback 未写成 Worker 的 `/callback`；或 `base_url` 填错。方案 B：Netlify Identity 未 Enable |
| 登录后看不到内容 | `config.yml` 的 `repo` / `branch` 与实际不符；确认仓库为 `用户名/仓库名` 且分支 `main` |
| 保存报错/不自动提交 | 用户对该 GitHub 仓库没有写权限（GitHub 后端要求有 push 权限） |
| PDF 预览空白 | 跨域或浏览器不支持预览；页面有"下载 PDF"按钮作兜底，移动端请直接下载 |
| 上传大文件失败 | Git 不适合超大文件，单 PDF 建议 <10MB；超大走 Cloudflare R2（见 README） |
| 构建失败 | 看 Cloudflare 构建日志；通常为 Hugo 版本，设 `HUGO_VERSION=0.165.0` |

## 8. 后续日常维护
- **改配色/文字**：编辑 `assets/css/main.css` 顶部 `:root` 变量，或 `config.yaml` 的 `params`。
- **换轮播图**：把照片放进 `static/images/`，改 `config.yaml` 的 `params.carousel` 路径。
- **新增菜单栏目**：改 `config.yaml` 的 `menu.main`，并新建 `content/<栏目>/` + `_index.md`。
- 所有改动都走 git 提交，Cloudflare 自动构建；本地可先用 `hugo server` 预览。
