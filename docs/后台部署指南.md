# 管理员后台（Decap CMS）部署指南

> 本文专讲**如何把 `/admin/` 内容后台真正用起来**（登录 + 上传校报 PDF + 发布文章）。
> 前置：网站已能在 Cloudflare Pages 访问（主页可打开）。本文默认你走**方案 A（Cloudflare + GitHub）**，
> 因为它与你现有 Cloudflare 托管一致、不依赖 Netlify。

---

## 0. 后台是什么、需要三样东西

后台地址：`https://你的站点/admin/`，底层是 **Decap CMS**。要让社员能"上传 → 自动存回 Git → 自动发布"，需凑齐：

1. **GitHub 仓库写权限**：Decap 把内容提交回仓库 `main` 分支（→ Cloudflare 自动重建）。
2. **登录认证**：社员登录后才能读写（本指南用 GitHub 账号登录）。
3. **（建议）一道 Cloudflare Access 门**：即使有 GitHub 权限，也要先过后台的访问白名单。

> 权限模型（本方案默认）：**凡是被你加入仓库且有写权限的 GitHub 账号，都能在后台登录并发布**。
> 若要"管理员审核后才上线"，见文末"审核流程"。

---

## 1. 创建 GitHub OAuth App（登录凭据）

1. 浏览器登录 **GitHub**（用你的管理员账号 `MTeaCase`）。
2. 打开：`https://github.com/settings/developers`
   （或 Settings → Developer settings → **OAuth Apps** → **New OAuth App**）。
3. 填写：
   - **Application name**：`Yuyi CMS Login`
   - **Homepage URL**：你的站点，如 `https://你的.pages.dev`
   - **Authorization callback URL**：**先随便填** `https://你的.pages.dev/admin/`（第 3 步部署完 Worker 后要改成 Worker 的 `/callback`）。
4. 点 **Register application**。
5. 记下 **Client ID**；再点 **Generate a new client secret** 生成 **Client secret**（**只显示一次，立即复制保存**）。

> 这个 App 决定了"用哪个 GitHub 账号体系登录"。请一定用你的主账号创建。

---

## 2. 部署 OAuth 代理 Worker（让 Decap 能提交 GitHub）

Decap 的 GitHub 后端需要"代理"完成授权换取 token（原因：GitHub 不允许纯浏览器跨域换取 token）。
仓库里已备好 `oauth-worker/`，部署为 Cloudflare Worker 即可。

### 2.1 安装并登录 Wrangler（在你电脑终端）
```bash
npm i -g wrangler
wrangler login          # 会打开浏览器授权 Cloudflare 账号
```

### 2.2 写入 Client Secret 并填入 Client ID
在仓库 `oauth-worker/` 目录：
```bash
cd d:\yuyipages\oauth-worker
wrangler secret put GITHUB_CLIENT_SECRET     # 粘贴第 1 步的 Client secret
```
编辑 `oauth-worker/wrangler.toml`，在 `vars` 段加一行：
```toml
GITHUB_CLIENT_ID = "粘贴你的 Client ID"
```

### 2.3 部署
```bash
wrangler deploy
```
记下输出的 **Worker 域名**，例如 `yuyi-oauth.你的子域.workers.dev`。

### 2.4 回到 GitHub，修正 Callback
回 OAuth App 编辑，把 **Authorization callback URL** 改为：
```
https://yuyi-oauth.你的子域.workers.dev/callback
```

> `oauth-worker` 的部署细节与本地测试见 `oauth-worker/README.md`。

---

## 3. 回填站点后台配置 `static/admin/config.yml`

打开该文件，把 backend 段改成真实值（去掉注释、替换占位）：

```yaml
backend:
  name: github
  repo: MTeaCase/yuyipages_beta   # 你的仓库
  branch: main
  base_url: https://yuyi-oauth.你的子域.workers.dev   # 第 2.3 步的 Worker 域名
  auth_endpoint: auth
  site_domain: 你的.pages.dev                 # 你站点的访问域名
```

并把文件顶部的 `site_url` 改成你的站点地址（如 `https://你的.pages.dev/`）。

> 目前仓库里的 `config.yml` 仍带占位符（`owner-name/repo-name`、注释掉的 `base_url`）。
> 把上面这些填好后保存并推送，Cloudflare 会重新构建；此时 `/admin/` 就能认 GitHub 登录了。

---

## 4. 用 Cloudflare Access 给 /admin 加一道访问门（强烈建议）

即便有 GitHub 权限，也先让后台经过一道"只放行你邀请的邮箱/账号"的门，防止后台地址泄露后被人随意访问。

1. Cloudflare 控制台 → **Zero Trust → Access → Applications → Add an application → Self-hosted**。
2. **Application domain**：填你的 Pages 域名（或自定义域名），**Path 填 `/admin`**。
3. **Policy**：命名 `社员`，Action **Allow**；规则可按你习惯选择：
   - 邮箱（Email）：填入允许的社员邮箱；或
   - 一次性验证码/社交登录：放行后自动发验证。
4. 保存。此后访问 `/admin/` 会先要求通过 Access，再进入 Decap 的 GitHub 登录。

> 若觉得两道登录麻烦，也可先跳过本节，直接靠 GitHub 写权限做门（第 5 步），以后再加 Access。

---

## 5. 邀请社员并赋予仓库写权限

Decap（方案 A）要求登录者对该 GitHub 仓库有 **push 权限**。

1. 让每个要发内容的同学拥有（或注册）一个 GitHub 账号。
2. GitHub → 你的仓库 → **Settings → Collaborators → Add people**，填入对方 GitHub 用户名或邮箱。
3. 把角色给 **Write**（能推送 main）。对方在自己 GitHub 收到邀请后点同意。
4. 把后台地址发给对方：`https://你的站点/admin/`，并告知用 GitHub 登录（走 OAuth App 授权）。

> 若个别同学不想用 GitHub，可考虑改用「方案 B：Netlify git-gateway」用邮箱密码登录，见文末附录。

---

## 6. 端到端测试（上线前务必做一遍）

1. 推送完第 3 步配置后，等 Cloudflare 构建成功。
2. 访问 `/admin/`：先过 Access 门（若配了）→ 点 **Login with GitHub** → 用有写权限的账号授权。
3. 进入后左侧应看到 **校报** 和 **文章** 两个集合（中文界面）。
4. **试发一期**：校报 → New → 填期数/日期 → 上传一个真实 PDF（<10MB）→ Save。
5. 回前台 `/newspaper/`，约 30s~1min 后能看到新一期、可预览与下载 PDF。
6. 再试发一篇文章 → `/posts/` 能看到。
> 第 4~5 步走通 = "上传 → 自动 commit → 自动构建 → 上线"整条链路 OK，后台部署完成。

---

## 7. 审核流程（可选，想让"管理员批准后才上线"）

默认是"谁登录谁发布"。若要审核：
- **方案 A 下**：直接在 GitHub 侧限制——只给 1~2 个主编 **Write** 权限，其余给只读，
  让他们把写好的内容以 PR 提出，由主编合并触发部署。
- 或改用**方案 B（Netlify + editorial_workflow）**：登录者保存后进"草稿"，由管理员点"发布"。
  方法：config 里 backend 用 `git-gateway` 并加 `publish_mode: editorial_workflow`，
  在 Netlify Identity 里控制谁能进（仅受邀）。

---

## 8. 常见问题排查

| 现象 | 处理 |
|---|---|
| `/admin/` 一直转圈 | Decap 脚本来自 unpkg CDN，需联网；或 config.yml 里 site_url 填错 |
| 点"Login with GitHub"没反应/报错 | OAuth App 的 Callback 没写成 Worker `/callback`；或 `base_url` 填错 |
| 登录后看不到内容 | `repo` / `branch` 与实际不符；确认仓库为 `MTeaCase/yuyipages_beta`、分支 `main` |
| 保存报错/无法提交 | 该 GitHub 账号对该仓库没有写权限（加到 Collaborators 且给 Write） |
| 上传 PDF 失败 | 单文件 >10MB 或网络不稳；超大走 Cloudflare R2（见 README） |
| 旧账号曾"被风控不能授权" | 那是账号问题，换用正常 GitHub 账号即可（本指南基于新账号） |

## 附录：方案 B（Netlify git-gateway）极简版

若你不想部署 Worker、希望社员用"邮箱+密码"登录：
1. 网站后台改用 Netlify：仓库连到 Netlify，构建 `hugo --minify`、输出 `public`。
2. `config.yml` 顶部 backend 换成：
   ```yaml
   backend:
     name: git-gateway
     branch: main
   ```
3. Netlify → **Identity → Enable → Invite users**，发送邀请邮件。
4. 需要审核则再加 `publish_mode: editorial_workflow`。

> 方案 A 能保住你的 Cloudflare Pages 托管；方案 B 更省事但要迁移到/搭配 Netlify。
